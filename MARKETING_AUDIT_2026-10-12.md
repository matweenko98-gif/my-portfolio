## Обязательное действие владельца: токен Telegram

На момент проверки токен обнаружен в настоящем публичном JavaScript сайта. Его значение не выводилось и не сохранялось в отчёт. **Нужно перевыпустить токен через BotFather**, затем установить в Vercel:

```text
TELEGRAM_BOT_TOKEN=<новый токен>
TELEGRAM_CHAT_ID=<существующий ID чата>
```

Удалить старую VITE_TELEGRAM_BOT_TOKEN и повторно развернуть сайт после обновления переменных. Сервер временно поддерживает прежние имена для совместимости, но старый раскрытый токен должен быть отозван. Не отправлять токен в чат. Пример переменных без секретов сохранён в `.env.example`.

После ротации доставку реальной заявки должен подтвердить владелец; аудит проверял её на заменённых ответах Telegram.

## Конверсии и аналитика

`lead_submitted` означает успешно подтверждённую доставку брифа, параметр `form_type=brief`. `contact_clicked` означает клик по контакту, параметр `contact_method=telegram|phone|email`; это не подтверждение заявки. Имена, номера, email, username, сообщение и полная ссылка контакта в события не передаются.

Для отчётов нужно отметить `lead_submitted` как ключевое событие GA4 и настроить соответствующие JavaScript-цели в Метрике. Настройки кабинетов в ходе задачи не изменялись. GA4 сохраняет существующий автоматический сбор просмотров; отдельные ручные page_view не добавлялись во избежание дублей. Настройки Enhanced Measurement кабинета не проверены.

## Границы проверки и оставшаяся работа

Аудит не гарантирует отсутствие любых возможных дефектов. Нет доступа к Search Console, Яндекс.Вебмастеру, статистике GA4/Метрики и администрированию Supabase: позиции, конверсии, полевые Core Web Vitals и политики RLS не подтверждены. CSP защищает от встраивания и опасных объектов, но не является полной строгой script-src-политикой. Ограничение частоты API действует в памяти экземпляра; для общей защиты всех экземпляров следует настроить Vercel Firewall либо распределённый лимитер.

Полноценная OAuth/MCP-интеграция в задаче не создавалась; её несуществующие интерфейсы больше не рекламируются. Для кейсов начальный серверный шаблон по-прежнему отдаёт краткое описание, а подробности загружает React. Полный SSR всех динамических CMS-компонентов — отдельная архитектурная задача; текущий аудит не выдаёт предварительный HTML четырёх статических страниц за полноценный SSR всей CMS.

После публикации повторить проверки HTTP/статических ресурсов/API на Vercel. Нельзя считать запись в GitHub доказательством успешного деплоя. Основной следующий этап безопасности — ротация раскрытого токена; следующий технический этап — миграция инструментов сборки Tailwind с проверкой оформления.
